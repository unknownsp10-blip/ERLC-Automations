DATA & PRIVACY

Privacy Policy

1. Overview

This Policy explains how the operator of the ER:LC Advanced Automation Bot (“the Bot”) handles information when a Discord server connects to an ER:LC private server. The Bot is designed to keep each Discord server’s configuration separate.

2. Information processed

Depending on enabled features, the Bot may process or store:

  • Discord identifiers: server, channel, user, and role IDs needed for permissions and routing actions.
  • ER:LC connection information: the server API key provided by an authorized administrator, connection status, and API response data.
  • Game/server information: server status, player names or identifiers, teams, permissions, vehicles, queue information, command and kill logs, staff information, moderator calls, and emergency-call information, to the extent available through the API and used by enabled features.
  • Automation configuration: names, triggers, conditions, actions, destinations, custom variables, cooldowns, and settings.
  • Operational records: execution history, timestamps, success/failure status, and diagnostic information.
  • Interaction information: information needed to respond to commands, buttons, menus, and other Bot interactions.

The Bot does not need your Discord password. Never submit one.

3. How information is used

Information is used to authenticate connections, provide Bot features, evaluate conditions, execute configured Discord or ER:LC actions, prevent duplicate executions, enforce permissions and rate limits, preserve configuration across restarts, protect the service, and diagnose errors.

4. API key protection

The project is designed to encrypt ER:LC server API keys at rest and keep them out of Discord messages and ordinary execution logs. This depends on the operator correctly protecting the encryption key and hosting environment. Administrators should keep keys confidential and rotate exposed keys.

5. Storage and providers

Bot configuration and operational data are stored in JSON files on the machine or hosting environment where the Bot runs. The hosting provider may process technical information such as server logs, IP addresses, and resource usage under its own policies. Discord and Roblox/ER:LC separately process information when the Bot communicates with their services. The operator does not control third-party privacy practices.

6. Sharing

The operator does not intend to sell personal information. Information may be transmitted to Discord or ER:LC to perform actions configured by a server administrator. Information may also be disclosed when reasonably necessary to comply with law, respond to valid legal process, protect users or the service, or investigate abuse. Do not configure automations to send information to unauthorized recipients.

7. Retention and deletion

Information is retained as long as needed to operate the Bot, preserve server configurations, maintain execution history, or address security and operational issues. Retention depends partly on hosting and backup settings. Removing an API key or deleting an automation may not erase historical records or backups. To request deletion of data associated with a Discord server, contact the operator below and identify the relevant server. Do not include API keys.

8. Security

The project includes safeguards such as encrypted API-key storage, server-specific data separation, permission checks, and protected file writes. No internet-connected service can be guaranteed completely secure. The operator should restrict access to hosting accounts, configuration files, backups, and encryption keys.

9. Children

The Bot is not designed to collect information directly from children. Users must comply with the age, consent, and usage requirements of Discord, Roblox/ER:LC, and applicable law.

10. International processing

Information may be processed or stored in countries other than yours, depending on hosting location and the locations of Discord, Roblox/ER:LC, and other service providers.

11. Changes

This Policy may be updated as the Bot’s features or data practices change. The “Last updated” date indicates the latest revision.
